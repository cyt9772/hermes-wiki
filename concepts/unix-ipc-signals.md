# 유닉스 신호와 프로세스간 통신 (Signals & IPC)

유닉스가 **독립 프로세스 사이로 알림·데이타를 전달하는 두 축** — **신호(가벼운 이벤트 알림)**와 **IPC(본격적 데이타 교환)**. APUE는 10장(신호)과 14·15장(IPC)으로 이 두 축을 체계화.

## 신호 (Signals) — 10장
프로세스(또는 OS)가 다른 프로세스에 **이벤트 발생을 통지**하는 경량 메커니즘. 데이타가 아니라 "무언가 일어났다"는 알림.
- **인용/처리**: `signal()` → `sigaction()`(POSIX 권장), `sigsetmask` 계열로 대기/차단
- **동시성 주의**: 유닉스(4.3BSD)는 신호를 대기시키지 않고 **단 한 번만** 처리 — 신호 재진입(중단된 처리 중 같은 신호 재발생)이 실제 버그 원인 `[raw/books/unix-advanced-programming.md]` ch10
- **동작**: 시그널 핸들러 등록, 디폴트 동작(종료·무시·스탑), `SIGALRM`(타이머) 등
- **계기**: 타이머, 외부 이벤트, 예외(예: SIGTERM으로 종료 요청)

## 프로세스간 통신 (IPC) — 14·15장
부모-자식·비부모 프로세스 사이 **양방향 데이타 흐름**. 난이도/기능 단계로 나뉨.

| 단계 | 메커니즘 | 특징 |
|------|---------|------|
| 기반(14장) | **파이프 (pipe)** | 부모자식 간, 단방향, 메모리 내. `pipe()`+`read/write` |
| 기반(14장) | **펩 (FIFO/이름 붙은 파이프)** | 비부자 프로세스도 가능, 파일시스템에 이름 노출 |
| 고급(15장) | **메시지 큐** | 메시지 단위 송수신, 순서 재배열 가능 (System V) |
| 고급(15장) | **세마포어** | 공유 리서스 동시 접근 제어(카운터) |
| 고급(15장) | **공유 메모리** | 가장 빠름. 세마포어와 함께 동기화 사용 |

- **System V vs BSD**: 메시지 큐·세마포어·공유메모리는 System V 계열, 파이프·FIFO는 BSD 계열 — 구현 표준이 섞인 "유닉스"의 실제 모습
- **프로토콜**: IPC는 "신호보다 무거우나, 데이타를 실어 나르는" 통신의 본질 — 네트워크 소켓과 개념이 동형(유닉스 도메인 소켓)

## 비교: 신호 vs IPC
| | 신호 (Signal) | IPC |
|---|--------------|-----|
| 용도 | 이벤트 **알림** | **데이타 전달** |
| 부하 | 매우 가벼움 (플래그) | 중간~무거움 (메시지/메모리) |
| 양방향성 | 보통 단방향 통지 | 양방향 송수신 |
| 동시성 이슈 | 재진입 | 세마포어/락 필요 |
| 비유 | "문 두드림" | "우편/전신" |

## 프로세스 세 가지 축 (8·9·10장)
APUE는 프로세스를 **제어(8장: fork·exec·wait) → 관계(9장: 부모/자식·세션) → 신호(10장)** 삼단으로 전개 — IPC(14·15장)는 이 삼단 위에 **데이타 플로우**를 얹는 확장.
